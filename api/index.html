IQ Labs API

Connect your lab's IQ Labs account to your own tools: a Telegram bot, n8n, Make, or your own software. Your program can find doctors, create cases, upload scans and photos, and follow each case through production. IQ Labs can also notify your program the moment a case arrives or changes stage.

Getting started

  1. In IQ Labs, sign in as an admin and open Settings → Integrations.
  2. Choose Create API key, give it a name such as "Telegram bot", and copy the key. It starts with iql_ and is shown only once.
  3. Call the API from your tool. Try this first; it returns your lab's name if everything is set up:
curl https://efjeeeztckovmtuzvefp.supabase.co/functions/v1/lab-api/v1/me \
  -H "Authorization: Bearer iql_YOUR_KEY"

All addresses below start with this base URL:

https://efjeeeztckovmtuzvefp.supabase.co/functions/v1/lab-api/v1

Requests and responses are JSON. Successful results are inside a data field. In the examples below, $BASE stands for this base URL.

Your API key

Send the key with every request, in either header:

Authorization: Bearer iql_YOUR_KEY
X-Api-Key: iql_YOUR_KEY
  • A key belongs to one lab and only ever sees that lab's data.
  • It acts as the admin who created it: cases it creates, accepts or advances are recorded under that admin's name.
  • It stops working when you revoke it in Settings, or if its admin is deactivated or is no longer an admin.
  • The API never returns prices, costs or payments.
Keep the key secret. Store it in your tool's credentials (in n8n, a "Header Auth" credential), never in a message, a shared sheet or a public repository. If it leaks, revoke it and create a new one.

Endpoints

MethodPathWhat it does
GET/meYour lab and which key is calling. Use it to test the connection.
GET/doctorsYour lab's doctors. Filters: phone, search (name), include_inactive, limit, offset.
GET/doctors/{id}One doctor, with their clinic.
GET/catalogCase types with their materials, shades and production stages, for building your menus.
GET/stagesEvery stage your lab uses, in board order.
GET/casesCases, newest first. Filters: doctor_id, stage_id, search (patient or case number), updated_since, include_cancelled, limit (max 200), offset.
POST/casesCreate a case. It arrives in Case Requests, the same as a doctor's own submission.
GET/cases/{id}One case with its pipeline, stage history and files.
POST/cases/{id}/acceptAccept a request; the case moves to the first stage of its type.
POST/cases/{id}/advanceMove the case one stage forward in its own pipeline.
POST/cases/{id}/filesUpload a photo, video or scan to the case.

Finding a doctor by phone

Phone numbers match however they were typed: 0770 123 4567, +964 770 123 4567 and 009647701234567 are the same number. A doctor with no number of their own matches on their clinic's number, but only when they are that clinic's only doctor; a number shared by several doctors never identifies anyone. If the lookup returns no doctor, ask the lab to save the doctor's own number in IQ Labs.

GET /doctors?phone=%2B9647701234567

{

      "has_portal_login": true,

What a case looks like

Every case response, list item and webhook uses this shape. Teeth use FDI numbering (adult 11–48, primary 51–85).

{
  "id": 3478,
  "case_number": 155,
  "case_label": "LAB-155",
  "group_id": 3478,
  "primary_case_id": null,
  "patient_ref": "Ali Hassan",
  "case_type": { "id": 527, "name": "Crown", "abbreviation": "CR" },
  "material": { "id": 482, "name": "Zirconia" },
  "shade": { "id": 5409, "name": "A2" },
  "adult_teeth": [11, 21],
  "child_teeth": [],
  "other_parts": null,
  "due_date": "2026-10-25",
  "is_rush": false,
  "note": "Please match the neighbouring teeth",
  "created_at": "2026-10-20T08:15:40Z",
  "accepted_at": null,
  "shipped_at": null,
  "cancelled_at": null,
  "submitted_by_doctor": true,
  "doctor": { "id": 384, "name": "Dr. Mohammed Al-Abadi", "phone": "0770 123 4567" },
  "clinic": { "id": 54, "name": "Smile Dental Clinic", "phone": null },
  "stage": {
    "id": 226, "name": "Requested", "color": "FF4472B8", "sort_order": -3,
    "is_intake_stage": true, "intake_kind": "requested",
    "is_terminal": false, "production_role": null,
    "changed_at": "2026-10-20T08:15:40Z"
  }
}

Stage names are whatever your lab calls them and can be renamed. For logic, use the stage's id, is_terminal (shipped), intake_kind (requested, needs_clarification, declined) and production_role.

Creating a case

curl -X POST $BASE/cases \
  -H "Authorization: Bearer iql_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "doctor_id": 384,
    "case_type_id": 527,
    "adult_teeth": [11, 21],
    "patient_ref": "Ali Hassan",
    "note": "Please match the neighbouring teeth"
  }'
FieldRequiredNotes
doctor_idYesFrom /doctors.
case_type_idYesFrom /catalog.
material_idNoDefaults to the type's default material.
shade_idNoMust belong to the type or material.
adult_teeth, child_teethNoArrays of FDI numbers.
patient_refNoPatient name or reference, up to 200 characters.
note, other_partsNoFree text.
due_dateNoYYYY-MM-DD. Defaults to the case type's usual number of days.
is_rushNotrue marks the case urgent.
primary_case_idNoAdds this case to an existing order with several case types (same doctor).

The answer is 201 with the new case. The case waits in Case Requests until someone accepts it in IQ Labs (or you call /accept). When the doctor has an IQ Clinics login, the case is priced automatically on acceptance, like any doctor submission; otherwise the lab sets the price in Case Requests.

Uploading files

Send the file as multipart/form-data in a field named file. Photos, videos, STL/PLY scans and PDFs are all accepted.

curl -X POST $BASE/cases/3478/files \
  -H "Authorization: Bearer iql_YOUR_KEY" \
  -F "file=@upper_scan.stl" \
  -F "note=Upper jaw scan"
  • Optional fields: note, file_type (photo, video or document; worked out from the file when omitted), uploaded_by (doctor, the default, or lab).
  • Up to 25 MB per file, 15 MB for a photo. Telegram bots can download files up to 20 MB.
  • Your lab's own attachment settings apply. If video is switched off in IQ Labs, a video upload is refused.

Webhooks

A webhook is an address of yours that IQ Labs calls automatically. Add one in Settings → Integrations → Add webhook and pick the events:

EventWhen
case.createdA new case is created: from the API, the IQ Clinics app, or the lab's own New Case.
case.stage_changedA case moves stage: accepted, advanced on the board or by QR scan, declined, or moved back.
pingYou pressed Send test. It carries your lab's latest case so you can map the fields.

Each event is a POST with these headers and a JSON body:

Content-Type: application/json
X-IQLabs-Event: case.stage_changed
X-IQLabs-Secret: whsec_...

{
  "event": "case.stage_changed",
  "event_id": 91234,
  "occurred_at": "2026-10-21T10:02:11Z",
  "api_version": 1,
  "lab": { "id": 96, "name": "Basra Advanced Dental Lab" },
  "case": { ...the case shape above, including doctor.phone... },
  "stage": { "id": 232, "name": "Quality Check", "is_terminal": false, ... },
  "previous_stage": { "id": 231, "name": "Fabrication", ... }
}
  • Check the secret. Compare X-IQLabs-Secret with the secret shown in Settings and ignore any request that doesn't match. In n8n, set the Webhook node's authentication to Header Auth with that header name and value.
  • Your address must start with https:// and answer within 10 seconds. Reply with any 2xx status.
  • IQ Labs sends each event once and does not retry. Settings → Integrations → Deliveries shows what was sent and how your address answered. If your service was down, catch up with GET /cases?updated_since=….
  • An order with several case types sends one event per case; they share a group_id.

Errors

Errors come back with a status code and a readable message:

{ "error": { "code": "unprocessable", "message": "adult_teeth must be FDI numbers 11-18, 21-28, 31-38, 41-48" } }
StatusCodeMeaning
400bad_requestSomething in the request can't be read: invalid JSON, a number that isn't a number, a missing file.
401unauthorizedThe key is missing, wrong or revoked, or its admin is no longer active.
403forbiddenThe lab's account is suspended.
404not_foundNo such route, or the doctor or case isn't in your lab.
422unprocessableUnderstood but not allowed: the case is cancelled, isn't accepted yet, the shade doesn't belong to the type, and similar.
500server_errorA problem on our side. Try again; tell us if it continues.

Telegram bot recipe

One way to build the bot in n8n. Telegram bots are free; create one with @BotFather and add its token to n8n's Telegram credentials.

  1. Know who is writing. On the doctor's first message, show Telegram's "Share my phone number" button (a reply keyboard with request_contact). Look the number up with GET /doctors?phone=… and save the Telegram chat id with the doctor's id. Accept the contact only when its user_id is the sender's own id.
  2. Build the menus. Load GET /catalog once and offer the case types, then materials and shades, as buttons.
  3. Create the case. Ask for teeth and patient name, then call POST /cases. Reply with the case_label, for example "LAB-155 received".
  4. Attach the files. For each photo or document the doctor sends, download it from Telegram and pass it to POST /cases/{id}/files.
  5. Tell the lab. A webhook on case.created posts "New case LAB-155 from Dr. …" to the lab's own Telegram chat.
  6. Tell the doctor. A webhook on case.stage_changed sends the doctor a message with the new stage.name, on Telegram (by the saved chat id) or on WhatsApp (by case.doctor.phone).
  7. Answer "where is my case?" with GET /cases?doctor_id=…&limit=5.
Automatic WhatsApp messages need your own WhatsApp Business Platform account from Meta: a phone number not used in the normal WhatsApp app, a verified business, and message templates Meta has approved. Meta charges per message. IQ Labs supplies the event and the doctor's number; your bot sends the message. To send a message by hand instead, at no cost, use Send via WhatsApp in a case's page in IQ Labs.

Limits and notes

  • Up to 10 active keys and 5 webhooks per lab.
  • limit on lists is 50 by default and at most 200; page with offset.
  • Lists sort newest first. Times are UTC in ISO 8601.
  • This is version 1. Fields may be added over time; existing fields keep their names and meaning.
  • Cases created by the API behave exactly like any other case in IQ Labs: they show on the Board, print, invoice and appear in reports as usual.
Questions or help setting it up: contact the IQ Labs team on WhatsApp.
